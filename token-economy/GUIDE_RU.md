# Экономия токенов в Codex и Claude Code

Инструкция для тех, у кого недельный лимит заканчивается за 2–3 дня.
Цифры ниже взяты из наших логов Codex и Claude Code за сентябрь 2026 и помечены как замер.
Ваши будут другими — проверьте их сами за минуту, раздел 2.

## 1. Почему лимит кончается

Агент отвечает не одним запросом к модели, а серией: прочитать файл, запустить команду,
подумать, ответить. Каждый такой вызов отправляет модели всю переписку целиком:
инструкции, историю, результаты команд.

**Расход ≈ число вызовов × размер переписки.**

- Новая ветка Codex весит 35–48 тыс. токенов ещё до вашего первого слова: в неё входят
  системные инструкции, список инструментов и скиллов. Замер: медиана 39 тыс. по 83 веткам.
- Дальше переписка растёт. В наших ветках средний вызов шёл при 120–130 тыс. токенов,
  а к концу длинной ветки — при 200–240 тыс.
- Одна ветка, в которой подряд задали 8 разных вопросов: 246 вызовов, 32 млн токенов.
- За два дня 44% расхода Codex дали ветки с 4+ вопросами, а 50% ушло на вызовы,
  где переписка уже была больше 150 тыс.

Кеш делает повтор той же переписки дешевле, но не бесплатным.
Считайте, что каждый вызов тратит лимит пропорционально длине всей переписки.

## 2. Проверьте себя за минуту

В наборе есть `usage_report.py`. Скрипт только читает логи на вашем компьютере
(`~/.codex/sessions` и `~/.claude/projects`), печатает цифры и не показывает текст переписки.
В сеть ничего не отправляет.

```bash
python3 usage_report.py --days 7
python3 usage_report.py --days 1 --top 5      # только сегодня
python3 usage_report.py --json > report.json  # для сравнения до и после
```

На что смотреть:

- **по дням** — сколько ушло за каждый день. Норма: недельный лимит / 7, то есть около 14% в день;
- **самые дорогие ветки** — флаги подскажут причину: «N вопросов в одной ветке»,
  «длинная переписка», «форк старой ветки», «тяжёлый старт», «сжималась N раз»;
- **где утекает** — какая доля расхода пришлась на многовопросные ветки и на длинную переписку.

## 3. Пять главных правил

1. **Один вопрос — одна ветка.** Новая тема — новая ветка, даже если «это быстро».
2. **Длинную ветку не продолжайте, а переносите.** Закончили результат или переписка
   стала тяжёлой — запишите короткую карточку и начните новую ветку с неё.
3. **Новая ветка — не форк.** Форк копирует историю: в нашем замере ветка-форк
   стартовала с 95 тыс. токенов вместо 39 тыс. и платила эту разницу в каждом вызове.
4. **Точная задача вместо «проверь всё».** Широкий запрос превращается в сотню вызовов.
5. **Тяжёлая модель — только для сложного.** В наших логах самая тяжёлая модель
   тратила недельный лимит примерно в 4 раза быстрее базовой на тот же объём.

## 4. Подробно

### Ветки

- Не задавайте в рабочей ветке вопросы про другие ветки («а почему там…», «посмотри ещё ту»).
  Каждый такой вопрос оплачивается всей накопленной перепиской. Спросите в новой ветке.
- Переносите, когда результат готов, когда следующая работа требует нового источника,
  или когда контекст заполнен примерно на 70%.
- **Дешёвый перенос.** Попросите агента записать карточку до 3 КБ: результат,
  доказательство, принятые решения, открытый вопрос, один следующий шаг.
  Откройте новую ветку сами и напишите:
  `Прочитай только <путь к карточке>. Шаг: <одно действие>. Старую переписку не открывай.`
  Такой файл обходится в 1–2 тыс. токенов, а новая ветка сразу работает от 40 тыс., а не от 200 тыс.
- Не просите агента самого создавать, проверять и архивировать ветки. У нас такой
  «автоматический перенос» занимал 19–48 вызовов (в среднем 28) внутри самой тяжёлой переписки.
- Готовая форма карточки — страница Capsule Lite в AI Starter.

### Запросы

- Давайте путь к файлу и что именно нужно, а не «найди где-то». Хорошо: «в `README.md`
  раздел Установка, проверь команды». Плохо: «проверь все файлы ещё раз».
- Просите сначала список файлов, потом чтение нужных строк. Один большой вывод команды
  добавляет 5–10 тыс. токенов и остаётся в переписке до её конца.
- Не вставляйте в чат длинные логи, выгрузки и дампы. Положите в файл и попросите
  прочитать конкретный кусок.
- Собирайте уточнения в одно сообщение. Пять коротких реплик подряд — пять пересылок
  всей переписки.
- Сразу пишите, когда считать работу готовой: «готово, когда тест проходит»
  или «когда в файле есть раздел X». Иначе агент продолжает проверять.

### Настройки

- **Модель.** Базовая — для текстов, правок, поиска. Тяжёлая — для сложного решения
  или трудного бага, и то в отдельной ветке. Уровень рассуждений в наших замерах влиял
  заметно меньше, чем число вызовов и длина переписки.
- **Файлы инструкций** (`AGENTS.md`, `CLAUDE.md`) уходят в каждый вызов. Держите их
  короткими: больше 5–10 КБ — повод сократить и заменить пересказы ссылками.
  В нашей настройке Claude Code из-за больших инструкций стартовал с 78 тыс. токенов.
- **Скиллы, плагины, MCP-серверы.** Каждый подключённый добавляет своё описание в каждый
  вызов. Отключите то, чем не пользуетесь неделю.
- **Дневная норма.** Раз в день смотрите использованный процент. Ушло больше 14% —
  запустите отчёт и найдите ветку, которая съела.

## 5. Команды

Терминальные версии:

| Действие | Codex | Claude Code |
|---|---|---|
| Новая чистая ветка | `/new` | `/clear` |
| Сжать текущую переписку | `/compact` | `/compact` |
| Что занимает контекст | `/status` | `/context` |
| Сколько лимита осталось | `/status` | `/usage` |
| Сменить модель | `/model` | `/model` |

В приложении Codex новая ветка — кнопка New thread. Сжатие экономит,
но теряет детали: для важной работы надёжнее карточка и новая ветка.

## 6. Скилл для агента

В наборе есть скилл `token-economy`. Он запускает отчёт, называет главные утечки
с цифрами и даёт правила только под них.

- Codex: скопируйте папку `skills/token-economy` в `~/.codex/skills/`.
- Claude Code: скопируйте её в `~/.claude/skills/`.

Затем напишите агенту: «лимит кончается — проверь, куда ушли токены».
Положите `usage_report.py` рядом или скажите агенту путь к нему.

Второй инструмент набора — `preflight/token_economy_audit.py`: он до вызова модели
проверяет, что выбранные файлы укладываются в бюджет контекста. Подробности — в `preflight/README.md`.

## 7. Как понять, что стало лучше

1. Сегодня: `python3 usage_report.py --days 7 --json > before.json`.
2. Неделю работаете по правилам.
3. Повторите в `after.json` и сравните расход по дням и число веток с флагами.

Процент экономии честно считается только так — по двум сопоставимым отчётам.
Набор не меняет настройки, не удаляет переписку и не отправляет данные.
